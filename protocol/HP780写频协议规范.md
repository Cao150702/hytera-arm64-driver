# 海能达 HP780 写频线 USB 协议规范(实测整理 v2)

> 2026-09-07 基于与官方 CPS 及自备电台的通信会话实测整理,并经 macOS libusb 直连验证。
> 完整原始数据:`hytera-protocol.json`(读频会话 72+72 帧)、`/tmp/usb-write.pcap`(写频会话)。
> **可用工具:`hp780_tool.py`(macOS 直连读频,已实测 95604 字节完整镜像)。**

## 1. 设备信息

| 项目 | 值 |
|---|---|
| VID / PID | 0x238B / 0x0A11(海能达/MCCI) |
| 设备类 | Class_FF(厂商自定义,非标准 CDC) |
| 配置 | 1 配置,1 接口(接口号 2),Class FF/FF/FF |
| 端点 | **EP1 OUT (0x01)** bulk 64B、**EP1 IN (0x81)** bulk 64B、EP2 IN (0x82) interrupt 8B |
| 字符串 | "DMR Radio"、"Hytera Communications" |

## 2. USB 控制层(枚举流程)

1. GET_DESCRIPTOR(device/config/string)× N
2. SET_CONFIGURATION(1)
3. **CLEAR_FEATURE(ENDPOINT_HALT)× 3**:对 0x81、0x01、0x82 各一次 —— MCCI 驱动初始化端点的标志动作(libusb 直连时此步可省略,实测不影响通信)

## 3. 数据帧格式(核心)

每个 USB bulk URB 承载完整一帧,帧结构:

```
偏移  长度  含义
0     1    0x7E 帧起始标志
1     1    类型: 0x00=保活/握手  0x01=CPS命令  0x04=对讲机应答
2     1    固定 0x00
3     1    标志字节 (正常 0x00,握手帧 0xFE/0xFD)
4     2    方向: 20 10 = CPS→对讲机; 10 20 = 对讲机→CPS
6     2    序号(大端): 命令帧恒 0x0000; 应答帧全局递增 0,1,2,3...
8     2    帧总长(大端,含 7E 头和校验尾)
10    2    prefix 字段(16-bit 大端,见 §4)
12    n    HRCP 包(见 §5)
```

**注意:len 字段 = 帧总长(不是 payload 长)。**

## 4. prefix 字段(d[10:12])

- 被电台固件校验,错则无应答(实测:垃圾 prefix → 超时)
- 与帧内容(地址、校验)相关;读块命令序列的 64 个值已完整提取为查表
- 部分规律:低字节 ≈ 0xA4 + (addr>>8),高字节 ≈ 0x54 - ceil((addr+cks)/256) + 借位,但有分段例外(k≥15、k≥22 各有偏移),暂未完全收敛,**工具用查表**
- 保活/识别等命令的 prefix 固定值见 §6

## 5. HRCP 包(帧内嵌套)

```
[02] [ax 2B 小端] [len_lo] [b] [data:len] [cks 1B] [0x03 固定尾]
```

- ax:命令号,应答时 +0x8000(如读块命令 0x01C7 → 应答 0x81C7)
- cks = `(~Σ(HRCP[1:-2]) + 0x33) & 0xFF`(8-bit 负字节和 + 0x33)
- 帧尾 2 字节 = [cks][03],03 是 HRCP 固定尾,不是校验
- 注:len 字段名义 2 字节,但高字节被 b 覆盖(len≤255 时等效 1 字节)

### 保活帧(无 HRCP 包,12 字节)

`7e 00 00 fe 20 10 00 00 00 0c 60 e5` → 应答 `7e 04 00 fd 10 20 00 00 00 0c 70 d2`
- 尾 2 字节 = **16-bit 1 的补码校验字**:整帧所有大端 16-bit 字相加 ≡ 0xFFFF

## 6. 读频会话流程(实测验证)

| 步骤 | CPS 发出(prefix 固定) | 应答 |
|---|---|---|
| 保活 | `7e0000fe20100000000c60e5` | 12B 握手应答 |
| 识别 | `...33d1 020502010000 2a03`(ax=0x0205) | 59B 型号信息 |
| 二次保活 | 同保活帧 | 12B |
| 模式查询 | `...31d3 020302010000 2c03`(ax=0x0203) | 91B |
| 参数读取 | `...02f1 02c50111...5b03`(ax=0x01C5,len=17) | 208B |
| 状态查询 | `...41c3 0201020100121c03`(ax=0x0201) | 91B |
| 安全交换 | `...08f3 02d30109...55 03`(ax=0x01D3) | 29B(应答慢,须补读) |
| **读块 ×64** | ax=0x01C7,len=12,data=`00 00 00 01 00 00`+addr(4B LE)+块大小(2B LE) | 块内容 |
| 结束 | `...f40f 02c601010000 6a03`(ax=0x01C6) | 20B |

**读块细节:**
- addr 从 0 开始每块 +0x5DC(1500),共 64 块 = 63×1500 + 1104 = **95604 字节**
- 末块大小字段 0x0450(1104),其余 0x05DC
- 块应答帧:`7e 04 00 00 10 20 seq 05 fc [prefix] [HRCP: 02 c7 81 e9 05 ...]`
  - 应答 HRCP ax = 0x81C7,len = 0x05E9(1513)
  - 块数据布局:帧 offset 17 起 data = `00 00 00 00 01 00 00`(7B)+ addr(4B LE) + dc05 + **块内容(1500B)**
  - **块内容 = 帧 [30:-2]**
- 读频数据两次会话对比 **100% 一致**(未加密)

## 7. 写频(已实测)

### 写参数命令(ax = 0x01CE)

```
帧: 7e 01 00 00 20 10 00 00 00 19 [prefix] 02 ce 01 06 00 [data 6B] [cks] 03
data: [参数ID 2B LE] [长度=2 2B LE] [值 2B LE]
```

- 应答回显:`02 ce 81 07 00 [01=成功] [参数ID] [02 00] [值]`
- **prefix 公式:`0x59A4 - (值>>8) + ((值>>8)<<8)`**(高字节 0x59-(值>>8),低字节 0xA4+(值>>8);实测参数 0x76 值 0x20/0x21 和参数 0x82 值 0x168 全部吻合)
- 写频会话流程:初始化(同读频)→ 读参数区(0xC7 参数式读命令,len=0x12,data 头 `00 00 00 00 01`+addr+`05 00`)→ 写参数(0xCE,每个写后跟 0x05 查询)→ 验证读回 → 0xC6 保存
- 完整写频会话重放实测 **144/144 帧全部有应答**;改参数值(0x20→0x21)重放同样全通过
- 参数 ID 语义(0x76/0x82/0xa6 对应 CPS 哪些设置)待映射;参数区读取的对齐细节待完善
